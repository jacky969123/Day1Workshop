## What this repo is

Snip is a tiny URL shortener built as a **superproject with one git branch
per layer**, each layer mounted here as a submodule. `main` (this branch)
only holds `.gitmodules`, docs, and `scripts/build-bundle.mjs` - no app code
lives directly on `main`.

## Layout & tech stack

| Path        | Branch     | Tech                          | What it is                              |
|-------------|------------|--------------------------------|-------------------------------------------|
| `backend/`  | `backend`  | Bun, zero deps                | HTTP API, in-memory store                 |
| `frontend/` | `frontend` | Angular 19                    | Web UI, calls the API via `HttpClient`    |
| `cli/`      | `cli`      | Node (CommonJS), zero deps    | `snip add/ls/open` CLI, calls the API via `fetch` |
| `bundle/`   | `bundle`   | Bun (generated)               | **Generated** single-process build for deploy (Docker/Railway) |

## API contract (change it everywhere or nowhere)

| Method | Path         | Body / Params      | Response                                                        |
|--------|--------------|---------------------|--------------------------------------------------------------------|
| POST   | `/api/links` | `{ "url": string }` | `201 { code, url, shortUrl, hits, createdAt }` or `400 { error }`  |
| GET    | `/api/links` | -                   | `200 [{ code, url, shortUrl, hits, createdAt }, ...]`               |
| GET    | `/:code`     | -                   | `302` redirect (increments `hits`), `404` if unknown                |

Backend, frontend, and CLI all depend on this exact shape. If you change it,
update `backend/server.js`, `frontend/src/app/snip.service.ts`, and
`cli/cli.js` together - never just one.

## Key commands

```sh
git clone --recurse-submodules <repo>   # plain clone leaves submodules empty
cd backend && bun start                 # API on :3000
cd frontend && npm install && npx ng serve   # UI on :4200
cd cli && node cli.js help
node scripts/build-bundle.mjs           # rebuild bundle/ locally (no push)
node scripts/build-bundle.mjs --push    # rebuild + commit + push bundle & main
```

## Edit -> push -> pointer-bump workflow

Submodules are independent checkouts of their own branch. To change
`backend`/`frontend`/`cli`:

1. `cd <layer>`, edit, `git commit`, `git push origin <layer>`
2. Back at repo root: `git submodule update --remote <layer>`
3. `git add <layer>`, commit the pointer bump, push `main`

Never edit `bundle/` this way - see Do/Don't below.

## Do

- Treat `backend/server.js`, `frontend/`, `cli/cli.js` as the source of truth;
  edit inside the submodule, then bump the pointer on `main`.
- Keep the API contract identical across backend/frontend/cli.
- Run `node scripts/build-bundle.mjs` (no `--push`) to preview a bundle
  rebuild before pushing.
- Update both `CLAUDE.md` and `.github/copilot-instructions.md` together.

## Don't

- **Don't hand-edit `bundle/`.** It's entirely generated by
  `scripts/build-bundle.mjs`; manual edits are overwritten on the next run.
- **Don't add `"type": "module"`** to `cli/package.json` or any `package.json`
  near `cli.js` - it's plain CommonJS and must keep running under `node`
  as-is, since the bundle copies it in unmodified.
- **Don't rename** the Angular project (`snip-frontend`) or change its build
  output location - `frontend/dist/snip-frontend/browser` is load-bearing:
  `build-bundle.mjs` fails loudly if it's missing.
- **Don't expect persistence.** Backend storage is an in-memory `Map` by
  design (demo simplicity) - data is lost on restart, and there's no
  database to configure.
- **Don't expect `bundle.yml` to run on every push.** It's schedule-only
  (+ manual `workflow_dispatch`) on purpose, so pushing to `backend`/`frontend`/`cli`
  doesn't trigger a rebuild storm across independently-pushed branches.
- **Don't confuse `docker.yml`'s `paths: bundle` filter with watching files
  inside `bundle/`.** It watches the `bundle` **submodule gitlink** entry in
  `main`'s tree, so it only fires when the bundle pointer is bumped on
  `main` (i.e. after `build-bundle.mjs --push`), not on commits made inside
  the `bundle` branch itself.
